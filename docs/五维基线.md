# crules 五维质量基线

> **定位**：五维（方法论 / 信息架构 / 机制化 / 分发 / 可维护性）的**基线快照 + 雷达演化**——把一次性外审结论固化为可对照资产，防对话丢失。属维护资产，**不复制、不占 plugin 分发 token**。
>
> **两条铁律**（v63 立）：
> 1. **触发式，非强制**——每轮改动只对照下「触发式检查表」，不触及则跳过；全维每轮自检 = gate 疲劳橡皮图章（元流程已超重，不再加仪式）
> 2. **重评须独立**——五维评分是定性判断，主控自评有自我拔高风险（AI 自评 ≠ 验证）；基线更新走独立上下文 subagent（`/review-review` 同款信息隔离），不自己改分

## 触发式检查表（收尾四问的第 4 问挂此表）

| 改动类型 | 维度视角 | 一问 |
|---|---|---|
| 改规则正文（CLAUDE.md / 进阶） | 方法论 | 新规则有无失败模式出处（谱系或实战）？是否又造无出处流程？ |
| 新增 / 移动文件、加链接 | 信息架构 | 孪生了吗（第二份同构内容）？常驻 token 净增多少？ |
| 改 hooks / scripts / agents | 机制化 | 声明与能力一致吗（error.md 教训）？软 / 硬层有没有错位标注？ |
| 改 README / commands / 分发路径 | 分发 | 出处戳？升级路径？消费方信任面？ |
| 改 docs 元文档 | 可维护 | 账本净增还是净减？轮次仪式有没有变重？ |

> 答案有「净下降」→ 记待办修正或当场改；有「净上升」→ 值得在 Changelog 提一句；全是中性 → 跳过，不留痕。
