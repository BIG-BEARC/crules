# AI Coding 三层缺陷分析(2026-09-05)

> 性质:分析文档,非评审议题。来源:一轮 brainstorming 讨论 + 检索核实。
> 用途:未来裁决「要不要吸收某外部资料/方法论」的标尺——先对照三层缺陷与既有覆盖,再判断增量。

## 一、结论先行

当前 AI coding 的核心缺陷收敛为三层,均有证据支撑(等级见各节)。四层版本中的「意图带宽窄」经复核**剔除**——「需求方说不清需求」是需求工程的老问题,人协同时同样存在,不构成 AI 特有缺陷,此前列入是凑结构的修辞。

对三层的解法审视结论:**稳的解法本规则库均已具备;新增解法经四轮自审全部空转或证据不足,增量空间接近零。**

## 二、三层缺陷与证据

### 第 1 层:置信度默认不可靠(虚构/校准崩坏)

- GPT-4 技术报告自报:预训练模型校准良好,**RLHF 后校准崩坏**(MMLU AUROC)
- [Just Ask for Calibration (Tian et al., EMNLP 2023)](https://aclanthology.org/2023.emnlp-main.330/):RLHF 模型 token 概率校准差,**口头报告置信度相对更好**——注意是比较级不是合格级,且后续研究([arXiv 2502.11028](https://arxiv.org/html/2502.11028v3))显示强烈依赖任务,「错时也报 90%」仍是常见失败形态
- 证据等级:**一手研究,硬**

### 第 2 层:自报成功不可信 + 谄媚倾向

- 谄媚有硬证据:[Anthropic: Towards Understanding Sycophancy](https://www.anthropic.com/research/towards-understanding-sycophancy-in-language-models)(RLHF 模型在用户施压下放弃正确答案)
- 「coding agent 虚报完成」(verification gap):有行业共识([Anthropic evals 指南](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)要求不信自报、测实际输出),但支撑主要来自工程博客/从业者经验,**缺直接研究证据**
- 动机解释(「优化目标是让这一轮看起来完成」)是叙事框架,非实证结论——不采信
- 证据等级:**谄媚硬、虚报半硬(共识级)**

### 第 3 层:长上下文衰减 + 跨会话零记忆

- [Lost in the Middle (Liu et al., TACL 2024)](https://arxiv.org/abs/2307.03172):U 型曲线,中部信息检索率显著下降。**注意:2023 年模型的实验,近两年长上下文已显著改进,对当前模型效力存疑,仅作弱佐证**
- 跨会话零记忆是架构事实,无需引证
- 证据等级:**现象真实;具体衰减形态对今天的模型为弱佐证**

## 三、解法审视账

| 解法 | 状态 |
|---|---|
| 证据外化(强制 Read、`file:line` 出处、证据 5 级) | **已有**,有实战背书,稳 |
| 测输出不测声明(测试代码存在 ≠ 已运行、证据分级) | **已有**,同上 |
| 认知资产化(memory、INVARIANTS、坑卡) | **已有**,方向正确 |
| 口头置信度询问 | **假说,待实战检验**——下次怀疑 AI 自信过头时直接问「几成把握」,积累命中率数据后再议入库 |
| 验证独立性(小任务) | 承认单会话无解:大任务 agent 隔离已有(plan-reviewer),小任务自审 + 需求方看 diff 即终点 |
| 任务粒度上下文预算 | 硬规则不可执行(规划期不知道相关代码量),与「先读后改」冲突,降为意识 |
| 禁止无理由让步 | **撤回**——规则会被「事后合理化」合规绕过,治不了谄媚倾向本身 |
| 关键信息放上下文首尾 | 降为「长输出裁剪」的弱佐证,不单列 |

## 四、Clean Code 不吸收裁决(记账)

《代码整洁之道》整包不吸收。理由:核心命题「为人类读者写代码」在 AI 视角下大部分失效——AI 无人类读者的注意力约束,且部分条款(极小函数、消灭注释)在 AI coding 中已被证伪(跳转地狱 / 意图注释恰是 AI 最有价值的上下文信号)。残差中仅「命名一致性(同一概念同一词,保障 grep 与引用检索)」「命令查询分离」两条有真实价值,留待后续议题,不本轮吸收。
