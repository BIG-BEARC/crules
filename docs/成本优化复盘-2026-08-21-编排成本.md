# 编排成本复盘与优化（2026-08-21）

> **源**：消费工程（saas_pos 三期）实战 usage 数据 + 主控自检。本文档是根因分析与优化方案的**单一沉淀**——v65 已落规则见对照表，v66 候选与消费侧吸收项待逐批执行。属维护资产，不复制、不占 plugin 分发。
> **诚实声明**：文中轮次/耗时为实测口径（代理 usage 报告）；token 量为级估算（50-150 万/代理、约一半重复阅读等）；优化后数字为推算，**待下个迭代实测对账**（对得上的进五维基线雷达，对不上的回补规则）。

## 二、成本模型（理解全部数字的钥匙）

```text
总成本 ≈ 轮次 × 单轮重量 × 单轮单价
```

**累积上下文计费**：每轮输入 = 任务书 + 此前全部工具结果。第 N 轮为前 N-1 轮的全部积累付费——长线程**尾部**每轮最贵。一次 30KB 的全量测试输出不是付一次钱：它落进历史后，**后续每轮重复计费**，直到会话结束。跑一次测试、付 60 次钱，就是「隐性成本」。

三个失误各占一项：sed/CWD 涨**轮次**、全量输出涨**重量**、发生在主线涨**单价**（主线每轮几万 token，全场最贵）。

## 三、六项成本根因

### 1. 实现代理长线程尾部（token Top1：50-150 万/代理）

- **现象**：T1 几十次 `flutter test` 全量输出（20-36KB/次）反复进上下文
- **根因**：累积计费 × 全量输出落历史；**层级错配**——DTO 纯逻辑测试用了最贵的 runner（`flutter test` 3-30 秒编译是固定开销，与用例数无关）
- **已落**：v65 §四「长输出先裁剪」（结论行 + 失败详情）；批量红绿砍轮数
- **待落**：分层 runner（纯逻辑 `dart test` 秒级）→ 消费侧附录；批量红绿的**断言有效性补偿**（防恒真断言，v66）

### 2. 主线自身（token Top2 / 耗时 Top5）

- **现象**：130+ 轮 × 每轮几万 token；15 轮纪律性返工：**sed**（shell 内联改测试文件，macOS 转义坏语法 → 6+ 轮）、**CWD**（每轮 Bash 后目录重置，反复踩 lib 不存在 → ~5 轮）、**漏 gen**（改 arb 未跑 gen-l10n → ~2 轮）
- **根因**：无成本意识的操作习惯 + 规则缺触发器（「改 i18n 先重跑生成」§四早有但没被遵守）
- **已落**：v65 §三「禁 shell 流内联编辑」「修订用局部 Edit 禁整文件重写」
- **待落**：复合命令（改 arb → gen → analyze 一行，消费侧附录）；Bash 显式绝对路径（习惯项）

### 3. 评审代理冷启动重复读（token Top3：每代理 20-87 轮 Read）

- **现象**：双关卡两代理各读同一批基准（设计/计划/在线版），T3 两关卡 112 次约一半是重复阅读
- **根因四层**：① 物理层——subagent 无共享内存（特性，砍不掉）；② **概念层（真根因）——「独立性」被实现为全面隔离，但需要隔离的只有判断，不需要隔离事实**（两个审计师看同一套账本，账本可共享、意见各出）；③ 操作层——基准集过宽（全量而非本次 diff 相关切片）+ 拉取过重（核 20 行却整读几百行文件）；④ 规则层——「核到 file:line」纪律只定义质量、没定义成本形态（与 TDD 逐用例同构，「质量规则无成本配套」第二例）
- **已落**：v65 关卡四级（双关卡/单代理双节/免复读/小任务并入）
- **待落**：**评审包契约化**（事实切片包 + 原路径抽查权——摘录不得成唯一信源，防主控摘录引入偏差）+ **定点读纪律**（核 file:line 用 offset/limit ±20 行窗口），v66

### 4. 调研→设计转写损耗（token Top4）

- **现象**：3 份长报告进主线 + 转写设计再输出一遍；rows / feeNum 等事实错误全部从转写进入
- **已落**：v65 事实核验前移（核验代理只核 file:line，比方案评审便宜一个量级）
- **待落**：**去转写**——核验后的调研报告直接作设计的事实小节（file:line 指针引用，不搬运内容），v66

### 5. 计划文档代码框架双写（token Top5：~1500 行约 40% 白写）

- **根因**：计划贴代码框架，代理实际照设计规格 + 范式自写（466 行弹窗为证）——框架双写纯浪费
- **已落**：v65 任务书契约化（文件清单 + 已核实签名 + 用例清单 + 红线；**写 1 读 N**——贴签名是 1 次核对换 N 个代理免读，贴框架是白写）

### 6. 设计文档全文重写（主线 token 成因之一）

- **现象**：v1→v3 全文重写 3 次，每次几千 token 输出 + 全文常驻上下文
- **根因**：AI 单轮操作经济学——结构性大改时 Edit 要精确匹配大段旧文，一次 Write 看似省事；**实为把 AI 的操作成本转嫁需求方**：diff 不可审（重读全文 vs 看增量）+ 上下文重复计费 + **已裁决内容被无声改动**（前几轮评审确认的措辞悄悄变了，评审闭环白做）
- **已落**：v65「修订用局部 Edit 禁整文件重写」
- **待落**：补**结构性推翻例外**（方向被否时重写是诚实行为，但须显式声明「本轮为重写非修订」+ 旧版归档），v66

## 五、v66 候选补丁（小改动批次）

1. 批量红绿**断言有效性补偿**：批量 RED 时抽查 1-2 个断言故意错值确认会红（工程化流程 §3 补一句）
2. 禁重写的**结构性推翻例外**：显式声明 + 旧版归档（CLAUDE.md §三补半句）
3. **评审包契约化**：事实切片包（基准节选 + 已核 file:line 清单 + 相关片段原文）+ 原路径抽查权保留（Agent编排成本分档节扩展）
4. **定点读纪律**：核 file:line 用 offset/limit 定点窗口，禁全文 Read 作背景（Agent编排/任务书契约处）
5. **调研去转写**：核验后报告直接作设计事实小节（工程化流程 §2 扩一句）
6. 附录模板**分层 runner 提示行**：纯逻辑 / 组件 / 集成测试命令分列（项目附录.md「构建·分析·测试命令」节）
