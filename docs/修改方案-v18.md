## 🔴 A — hooks 硬执行（最高优先）

### 现状

`CLAUDE.md` 最硬的几条红线全是 prompt 软约束：

- §二「禁止自动提交」
- §二「破坏性操作必须二次确认」
- §六「后台 agent 完成必须展示 diff」

### 问题（为什么是最高优先）

crules **三次**诊断"派生滞后"复发，根因结论是 **"纪律写了 ≠ 生效"**（评审.md v16「核心洞察」），治本要"硬机制"。它在两个层面开了药：

- INVARIANTS.md 的「可执行检查」（测试硬拦）
- v13 续 A/B2（元触发表 + checklist，已标缓办）

**唯独在最直接的 hooks 层没开药**——crules 教别人"约束光文档没用，要机制硬拦"，自己最硬的红线却全靠 AI 自觉。这是 **dogfooding 第四个盲区**：同一个病第四次复发，且解药（Claude Code hooks）是现成的。

### 方案

随包发 hook 模板，`/crules-init` 复制到项目的 `.claude/`。新增目录：

```
crules/hooks/
├── settings.json            # 模板：注册 2 个 PreToolUse hook
├── git-commit-guard.sh      # hook 1：禁自动 git commit/push
└── destructive-guard.sh     # hook 2：破坏性操作 ask 二次确认
```

**hook 3（后台 diff 提醒）建议缓办**——见末尾"为什么不全 hook 化"。

#### 文件 1：`crules/hooks/settings.json`（模板，复制到项目 `.claude/settings.json`）

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/git-commit-guard.sh"
          },
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/destructive-guard.sh"
          }
        ]
      }
    ]
  }
}
```

#### 文件 2：`crules/hooks/git-commit-guard.sh`

```bash
#!/usr/bin/env bash
# crules §二 硬执行：禁止自动 git commit / push，除非最近一条用户消息含授权词
# 机制：读 transcript 最近 user 消息，grep commit|push|提交；命中才放行
set -euo pipefail
input=$(cat)
cmd=$(printf '%s' "$input" | jq -r '.tool_input.command // ""')

# 只管 git commit / git push，其余放行
if ! printf '%s' "$cmd" | grep -qE '\bgit[[:space:]]+(commit|push)\b'; then
  exit 0
fi

# 读 transcript 最近一条 user 消息，查授权词
transcript=$(printf '%s' "$input" | jq -r '.transcript_path // ""')
authorized=0
if [ -n "$transcript" ] && [ -f "$transcript" ]; then
  last_user=$(grep '"role":"user"' "$transcript" 2>/dev/null | tail -1 || true)
  if printf '%s' "$last_user" | grep -qiE 'commit|push|提交'; then
    authorized=1
  fi
fi

[ "$authorized" = "1" ] && exit 0

# 阻断，原因回灌给 Claude（结构化 permissionDecision）
cat <<'JSON'
{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"crules §二 禁止自动提交：未在最近用户消息检测到 commit/push/提交 授权。如确需提交，请用户在对话中明确发送 commit/push/提交。"}}
JSON
exit 0
```

#### 文件 3：`crules/hooks/destructive-guard.sh`

```bash
#!/usr/bin/env bash
# crules §一/§二 硬执行：破坏性 / 不可逆操作交用户终端二次确认（ask）
set -euo pipefail
input=$(cat)
cmd=$(printf '%s' "$input" | jq -r '.tool_input.command // ""')

# 命中破坏性模式 → ask（终端交用户确认）
if printf '%s' "$cmd" | grep -qE '\brm[[:space:]]+-rf\b|git[[:space:]]+reset[[:space:]]+--hard\b|git[[:space:]]+push[[:space:]]+(-f|--force|.*--force-with-lease)\b|git[[:space:]]+clean\b|git[[:space:]]+branch[[:space:]]+(-D|--delete)|git[[:space:]]+checkout[[:space:]]+\.[[:space:]]*$'; then
  cat <<'JSON'
{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"ask","permissionDecisionReason":"crules §二 破坏性操作：此命令不可逆，需用户明确确认后再执行。"}}
JSON
  exit 0
fi
exit 0
```

### 验证方法

1. 装好后，不说话直接让 AI 试 `git commit -m test` → 应被 hook 拒，AI 转述"需用户授权"。
2. 用户发"提交" → 再让 AI commit → 放行。
3. 让 AI 跑 `git reset --hard HEAD~1` → 应弹终端确认。
4. 普通 `ls`/`git status` → 不受影响。

> **⚠️ hook 语义随 Claude Code 版本演进**：结构化 `permissionDecision` 字段为近期版本用法。落地前用 `claude --version` 对照[官方 hooks 文档](https://docs.claude.com/en/docs/claude-code/hooks)核对字段名。若版本较旧，退回**通用兜底**：脚本 `exit 2` + 把原因打到 stderr（任何版本都生效）。**设计本身（查 transcript 授权词 / 破坏性模式 ask）与版本无关，稳定。**

### 为什么不全 hook 化（hook 3 缓办）

- §六「后台 agent 完成展示 diff」若做成 Stop hook，**每次停止都弹**，噪音大；且后台 agent 改动难以在 hook 里精确归因。
- 该条已是 CLAUDE.md §六 + Agent编排.md 双写、表述清晰，prompt 遵从够用。
- **结论**：hook 1/2 收益高、噪音低，先上；hook 3 留作 prompt，等痛感出现再机制化。
