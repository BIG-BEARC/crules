## 文档维护规则

- **已确认落地 / 已决议的项** → 在 [`待办.md`](待办.md) 标 ✅，并移入本文件「已关闭 / 已决议」表
- **已关闭积累到量或里程碑**（如某大建议整套落地、或 >8 条）→ 批量移 `archive/`，本文件只留 Changelog 一句话摘要
- 本文件维持 **「Changelog + 最新详情 + 已关闭」** 精简形态（待办自 v44 起独立于 [`待办.md`](待办.md)）；已关闭不占主视野，但 archive 全文 + Changelog 摘要双保险，不丢审计链
- 符号：🔴 重要 / 🟡 中等 / 🟢 小优化；✅ 已落地；🔒 已决议锁定（不再列为待收）
- **总览同步检查（防派生滞后，dogfooding）**：模板文件增删 / 能力新增的改动，收尾**必查**根 `README.md` + 子目录 `README.md` 的「文件清单 / 规模表 / 启用决策表」是否反映；未反映 = 改动未完成。查询源：[`CHANGELOG.md`](CHANGELOG.md)

| 已关闭表 >8 行 | 批量归档 `archive/`（L11） | I2 查 |
| 纯笔误 / 措辞修正（无行为变化） | 不进 CHANGELOG（口径：**记能力，不记笔误**） | — |

### 收尾三问（v13续-B2，v55 落地——每问挂机器检查，能查的不靠人记）

1. **本轮有分发文件的行为 / 能力 / 内容变化吗？** 有 → CHANGELOG 加段了吗（判定见上表第 2/5 行——v52 N8 复发、v54 D8 漏记都是这问没问）
2. **待办池与本文件同步了吗？** 状态变化先改待办再记轮次（I1 看守残留）
3. **账本膨胀了吗？** 已关闭 >8 行归档（I2 看守）、Changelog 行守一句式（v37 起纪律）
