## §3 新发现（本轮核对抓到）

### 🟡 N1. Agent编排.md `main` 与"主控"术语残留不一致

- **位置**：`进阶/Agent编排.md:57,69,75,108`
- **问题**：本篇第 11–13、37 行已明确"主控即主对话"、角色表用"主控"（`main.md` 已移除）。但第 57 行"跨层架构调整 | **main**（设计）+其他"、第 69 行"必须先由 **main** 评估"、第 75 行"**main** 设计数据层"、第 108 行"收到需求→**main** 做需求讨论"仍用 `main`。
- **性质**：`main.md` 移除后的术语残留——v5/v6 没抓到（当时 main.md 还在）。读起来"主控"与 `main` 混指同一角色，易误以为还有个 main agent 文件。
- **建议**：四处 `main` → "主控"。

### 🟡 N2. 记忆库触发表两处逐行重复（违反"权威正文单一"）

- **位置**：`进阶/记忆库体系.md:46-64` vs `memory/MAINTENANCE.md:8-22`
- **问题**：两张"你做了什么→必须更新"表内容几乎完全相同（11 行逐行对应）。通用包 `README.md:78` 和记忆库体系:132 都强调"权威正文单一、避免多个不一致版本"，但这两张表正是重复。
- **建议**：MAINTENANCE.md（运行时卡片）的触发表精简为"见 `进阶/记忆库体系.md` 触发即更新"，只保留它独有的"维护时机优先级 + 自检清单"；或反过来让体系篇引用 MAINTENANCE。二选一，去掉一份重复正文。

### 🟢 N3. app/plugin §四自写 superpowers 工作流表，与 ownership 表措辞张力

- **位置**：`flutter/app/CLAUDE.md:103-123`、`flutter/plugin/CLAUDE.md:93-111` vs `flutter/README.md:232`
- **问题**：ownership 表（flutter/README:232）写"superpowers/spec-kit 工作流映射 → 引用，不自写"。但 app/plugin §四各自**自写**了一张完整 superpowers skill 映射表（brainstorming/writing-plans/TDD/...），与 `插件工作流.md` 的 superpowers 列重叠。
- **辩解**：两者维度确有不同——app/plugin §四是"Flutter 任务每步哪个 **dart-flutter** skill 配合"（Flutter 专属），插件工作流.md 是"每个 Gate 用哪个**流程** skill"（通用）。dart-flutter 列是 app/plugin 独有、不重复；重叠只在 superpowers 列。
- **建议**：ownership 表措辞细化，区分两层——"流程层 skill 映射（superpowers/spec-kit，引用插件工作流.md，不自写）" vs "Flutter 任务层 skill 配合（dart-flutter，app/plugin 自维护）"。避免读者误以为 app/plugin §四的整张表都该删。

### 🟢 N4. flutter/app §四 PRD 仍写死 `prd-<feature>.md`

- **位置**：`flutter/app/CLAUDE.md:123`
- **问题**：跨模块大改动仍"输出 PRD（`.claude/plans/prd-<feature>.md`）"，未像通用包工程化流程:17 那样接 `/speckit`。
- **辩解**：flutter 模板定位是"superpowers + dart-flutter"组合，通篇没提 spec-kit，不接 `/speckit` 有合理性。但用户若同时装了 spec-kit，这里与通用包措辞不一致。
- **建议**：可加一句"若启用 spec-kit，用 `/speckit` 产出 spec 替代 prd-<feature>.md"，与通用包对齐；或保持现状（flutter 模板自洽于双插件场景）。优先级低。

### 🟢 N5. CLAUDE.md §八"在上方任一处加入"指代不清

- **位置**：`CLAUDE.md:232`
- **问题**：§八"若项目启用 `.claude/memory/`，在上方任一处加入以下声明"——"上方任一处"指代模糊（CLAUDE.md 任意位置？项目附录？）。且 §七表已有"记忆库维护→memory/"入口，§八又独立成节讲记忆库加载，两者略割裂。
- **建议**：明确为"复制以下声明到项目 `CLAUDE.md` 开头或 `项目附录.md`"；或把 §八的声明块并入 §七入口表下方，减少节 fragmentation。

### 🟢 N6. app/plugin 后台 diff 段无 AUTO-SYNC 标注

- **位置**：`flutter/app/CLAUDE.md:180-188`（§九）、`flutter/plugin/CLAUDE.md:191-199`（§十）
- **问题**：这两段与通用包 `CLAUDE.md §六` 内容重复。ownership 表（flutter/README:233）写"验证纪律/后台 diff → AUTO-SYNC（可选）"，但 app/plugin 这两段实际**无条件自写、无标注**。
- **辩解**：app/plugin 把后台 diff 写成无条件生效有道理（Flutter 项目常用子 agent），通用包 §六则是"启用 Agent 编排才生效"。语义不同。
- **建议**：要么给这两段加 `AUTO-SYNC` 标注（与 ownership 表"可选"对齐），要么 ownership 表改为"flutter 自维护（无条件生效）"。二选一消除措辞与实际不符。
