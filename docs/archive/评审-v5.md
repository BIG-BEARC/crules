## §1 架构级问题（最高优先）

### 1.1 🔴 通用包没桥接 spec-kit+superpowers →【已定方向：混合方案】

- **CLAUDE.md §3 = 基线 + 硬指针**：基线为零依赖双 Gate（需求 Gate 用 `AskUserQuestion` 澄清六要素；方案 Gate 用 `EnterPlanMode` 出计划、`ExitPlanMode` 获批）。末尾加 3-5 行硬指针：
  > 若附录「工具链」启用 spec-kit/superpowers，开始任何 Gate 前**必须先 Read** `进阶/插件工作流.md`，按其映射执行。
- **新增 `进阶/插件工作流.md`**：完整 skill 映射表（紧凑一页），见 §5.1。
- **附录加工具链配置位**（见 2.3#1），填"启用"→触发上述必读硬规则。
- 理由：完整映射不进 CLAUDE.md（避免撑大根文件、避免纯规则用户加载噪音）；进阶篇天然门控；硬指针保证 AI 启用插件时去读。

### 1.2 🔴 两套 CLAUDE.md 重叠 →【已定方向：A' 强化版 + ownership 表】

- **A' 生成式同步，范围扩到所有重叠段**（不只红线）：红线 + 提交 + **superpowers 工作流映射**（superpowers 是通用插件，权威归通用包）。flutter/app 独有的是 dart-flutter 映射 + Flutter 技术栈/分层/TDD/checklist。
- **flutter/app 重复段标 `<!-- AUTO-SYNC FROM 通用项目规则模板包/CLAUDE.md §X -->`**，由同步脚本刷新；flutter/app 仍自包含可复制。
- **新增段 ownership 表**（见 §5.2），文档化"哪些同步、哪些独有"——A' 落地的纪律文件。
- 理由：A' 让"自包含"与"单一权威"兼得；叠加模式牺牲自包含，不选。

### 1.3 🔴 分层错位：Flutter 内容混入通用层

Flutter 专属（agents 的 frontend/backend/i18n/platform、checklist 移动端条目、NAVIGATION 的 widgets/views/providers、工程化模块清单）挪到 `flutter/`；通用包留中性骨架。详见 2.4#1、2.5#1、2.8#2、2.9#1。
