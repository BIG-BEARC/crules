# 进阶能力

> 本目录是 [`../CLAUDE.md`](../CLAUDE.md) 之外的可选能力。根规则自包含、独立生效；进阶篇只在对应场景启用，不复制也不影响根规则。
> 进阶篇**不重复**根规则（提交、范围、不虚构等），只补充各能力的专门纪律。

---

## 启用决策

| 进阶篇 | 何时启用 | 解决什么 | 建议规模 |
|---|---|---|---|
| [审查与复核纪律.md](审查与复核纪律.md) | 项目需要 code review / 资损评估 / 安全审计 | 业务可达性 Gate、子代理结论复核、资损评级克制、专家否决、Review Checklist | 标准 |
| [工程化流程.md](工程化流程.md) | 需求涉及新页面 / 跨模块 / 多端 / 大重构 | PRD 分模块、任务粒度（2–5min）、两阶段审查时机、worktree、交付汇报模板 | 标准 |
| [Agent编排.md](Agent编排.md) | 使用多 agent 协作 | 主控（不写码）+ 角色分工、串并行调度、主控复核责任、协作纪律 | 重度 |
| [记忆库体系.md](记忆库体系.md) | 项目大到需要代码索引 / 决策日志 | `.claude/memory/` 结构、触发即更新、索引与决策格式、权威正文单一 | 重度 |
| [方案评审闭环.md](方案评审闭环.md) | 大需求方案需独立评审 | 实施前第三方方案评审、角色四分、7 步闭环、循环守卫、评审纪律 | 标准（大需求） |
| [插件工作流.md](插件工作流.md) | 装了 superpowers / spec-kit | 工作流 skill 映射、选 superpowers 还是 spec-kit | 任意（装插件时） |

- **轻量项目**：不需要本目录任何文件
- **标准项目**：复制审查纪律 + 工程化流程
- **重度项目**：全复制（含 Agent编排 + 记忆库体系，并配 `agents/`（部署位 `.claude/agents/`）与 `memory/`（部署位 `.claude/memory/`））

---

## 怎么启用

```bash
# 按需复制对应篇到项目根的「进阶/」目录（保持 ../CLAUDE.md 路径成立）
mkdir -p <你的项目>/进阶
cp 审查与复核纪律.md <你的项目>/进阶/
cp 工程化流程.md     <你的项目>/进阶/
cp 方案评审闭环.md   <你的项目>/进阶/  # 大需求方案评审
# 重度再加：
cp Agent编排.md      <你的项目>/进阶/
cp 记忆库体系.md      <你的项目>/进阶/
# 装了 superpowers / spec-kit 再加：
cp 插件工作流.md     <你的项目>/进阶/
```

> 也可把进阶篇内容直接合并进项目 `CLAUDE.md`（小项目推荐，少一层目录）。合并时去掉文件头的「启用条件」与交叉引用路径，保持单一文件。

---

## 与根规则的关系

- 根 [`../CLAUDE.md`](../CLAUDE.md) 定义**所有项目都适用**的红线、双 Gate 工作流、验证证据、完成定义
- 进阶篇定义**特定场景才用**的专门纪律，引用根规则时只链接不复制
- 冲突时以根规则为准（根是权威正文）

## 路径约定

进阶篇内 `../CLAUDE.md` 指「项目根的 CLAUDE.md」，假设本目录（`进阶/`）位于项目根下。若你把进阶篇放到别的位置或合并进根文件，相应调整或删除这些引用。
