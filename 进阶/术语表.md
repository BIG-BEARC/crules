# 术语表

> **启用条件**：阅读规则文档遇生词时查（按需读取，不常驻）。一行一术语：定义 + 权威出处文件。bus factor=1 的最低成本解——第二个人入门的钥匙（v68）。

| 术语 | 一句话定义 | 权威出处 |
|---|---|---|
| **需求方** | 下达指令的人（开发者 / 委托方）；「用户」则指软件最终使用者 | [`../CLAUDE.md`](../CLAUDE.md) 头注 |
| **双 Gate** | 需求 Gate（六要素确认）+ 方案 Gate（七要素确认）两道实施前闸门 | `../CLAUDE.md` §三 |
| **确认点** | 流程中必须停下等需求方显式回复的位置（防顺流自动推进） | [`方案评审闭环.md`](方案评审闭环.md) |
| **证据 5 级** | 静态 / 构建 / 测试环境 / 目标环境 / 生产——禁止笼统说「已验证」 | `../CLAUDE.md` §四 |
| **L0-L2 可达性** | 审查发现的业务可达性分级；AI 上限 L1，L2 须需求方确认 | [`审查与复核纪律.md`](审查与复核纪律.md) |
| **两阶段审查** | 规范合规与代码质量分两轮独立输出，不混视角 | [`审查与复核纪律.md`](审查与复核纪律.md) |
| **角色四分** | 方案产出者 / 第三方评审 / 派发转交 / 裁决（需求方唯一拍板） | [`方案评审闭环.md`](方案评审闭环.md) |
| **循环守卫** | 方案评审最多 3 轮，同点分歧升级需求方终裁不拉锯 | [`方案评审闭环.md`](方案评审闭环.md) |
| **三档** | Lite / Team / Advanced 安装规模，从 Lite 起步按需升 | `../README.md` |
| **轻装 / 完整模式** | 轻装=CLAUDE.md 仅 `@` 导入+覆写节（源更新自动生效）；完整=全量 cp（复制即分叉） | `../commands/crules-init.md` |
| **版本戳** | 安装时落盘的 `<!-- crules: vX.Y.Z @ 日期 -->` 出处标记，巡检锚点 | `../scripts/check-imports.sh` 头注 |
| **覆写优先** | 本项目覆写节压过 `@` 导入的规则正文 | `../CLAUDE.md` §一 |
| **门控（启用条件）** | 进阶篇默认不加载，带触发条件用到才读 | 各进阶篇头注 |
| **信任档位 / 提速档** | 附录可声明的流程减压阀（扩大极简范围）；仅需求方可调，AI 不得自升档 | `../CLAUDE.md` §三 + 附录「协作偏好」 |
| **漂移队列** | `.claude/memory/.pending-updates`——PostToolUse 自动记录的索引待补清单 | `../hooks/pending-updates.py` |
| **对抗样本库** | 每次绕过事故先加 fixture 再修（红→绿），测试即攻击样本沉淀 | `../hooks/test_deny_list.py` |
| **任务书契约化** | 任务书只含文件清单/已核实签名/用例清单/红线，不含代码框架（写 1 读 N） | [`Agent编排.md`](Agent编排.md) |
| **评审包契约化** | 评审输入=事实切片包+抽查权；隔离的是判断不是事实 | [`Agent编排.md`](Agent编排.md) |
| **批量红绿** | 同构用例集写完→1 轮 RED→实现→1 轮 GREEN（替代逐用例循环） | [`工程化流程.md`](工程化流程.md) §3 |
| **事实核验前移** | 调研报告先派便宜核验代理只核 file:line，再进设计 | [`工程化流程.md`](工程化流程.md) §2 |
| **禁静默覆盖** | 老项目合并最高纪律：既有文件先体检备份取舍，永不无声替换 | `../commands/crules-init.md` 2b |
| **单一权威正文** | 同一规则只留一份权威版本，其余位置只链接不复制 | `../README.md` 维护原则 |
| **触发式检查表** | 五维（方法论/IA/机制化/分发/可维护）改动视角表——触及才查，非强制 | `../docs/五维基线.md` |
| **deny-by-default** | deny-list 拦截原则：无歧义破坏命令一律拦、不做意图判断、被拦归人工 | `../hooks/deny-list.py` 头注 |
