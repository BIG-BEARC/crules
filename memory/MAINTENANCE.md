# 记忆库自动维护规则

> AI 在项目工作时，按本文件**主动维护** `.claude/memory/`。
> 完整格式模板与体系说明见通用包 `进阶/记忆库体系.md`（若已集成）；本文件只保留**运行时必备**，自包含可用。

## 触发即更新（强制）

> 本表与通用包 `进阶/记忆库体系.md` 的「写代码后必须更新」表保持一致，改动同步。

下列操作完成后，**同一轮对话内**必须更新对应索引，不能拖到下次：

| 你做了什么 | 必须更新 |
|---|---|
| 新建 / 重命名 / 删除源代码文件 | 对应 `indexes/*.md` |
| 新增状态单元 / 业务逻辑模块 | 对应状态索引 |
| 新增可复用组件 | 组件索引 |
| 新增工具 / 扩展 / 混入 | 对应索引 |
| 新增 / 修改路由入口 | 路由索引 |
| 新增数据模型 / 枚举 / 配置 | 对应索引 |
| 新增数据层模块（仓储 / 拦截器） | 对应索引 |
| 新增协议命令 / 接口分组 | 对应索引 |
| 新增国际化分组 | i18n 索引（只记分组，不记单 Key） |
| 做出影响多模块的架构决策 | 新建 `decisions/YYYY-MM-DD-<slug>.md` |
| 发现并固化项目特有代码模式 | 追加到 `patterns.md` |
| 业务流程 / 接口契约变更（影响可达性判定） | `business-rules.md` 对应条目 |
| 硬技术约束 / 不变量变更（影响正确性） | `INVARIANTS.md` 对应条目 |

**判定标准**：如果改动会让「未来 AI 找东西的路径」发生变化，就必须更新。

## 维护时机优先级

1. **写代码时顺手**（最高）→ 2. **决策做出时立即** → 3. **`/update-memory` 兜底** → 4. **会话结束前自检**

## 不维护原则

不写完整 API 文档（源码的事）· 不复制代码（引用源文件路径）· 不记生成文件 · 不记 git 能查到的信息。

## 自检清单（每轮对话结束前）

- [ ] `.claude/memory/.pending-updates` 非空？（PostToolUse 自动记录的漂移队列——本轮改过哪些源文件，对应索引补了吗？补完清空该文件）
- [ ] 新建 / 删除 / 重命名了源文件？对应索引同步了吗？
- [ ] 新增状态单元 / 组件 / 路由吗？索引有登记吗？
- [ ] 做了影响后续编码的设计决策吗？有 decision 文件吗？
- [ ] 发现「其实项目里已有这个工具」？要不要补到 `patterns.md`？
